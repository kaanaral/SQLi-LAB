    04 — report

    Why this worked

    Your input gets pasted straight into the query:

    f"... WHERE username LIKE '%{keyword}%'"

    So anything that looks like SQL just runs as SQL.

    The fix

    Send the value separately from the query, instead of pasting it in:

    cur.execute( "SELECT username FROM credentials WHERE username LIKE ?", ('%' + keyword + '%',) )

    No leak this time

    The UNION payload didn't return any extra rows. Either the query is parameterized (safe), or there are no registered users to extract yet — try /register first.

    Good to know

    The same bug could leak the whole table, not just a few rows.
    It can bypass logins too, not only search boxes.
    One fix covers it all: use parameters anywhere user input meets SQL.
